| R-01 | Major | aidlc/spaces/default/intents/261112-p1-ui-redesign/construction/u5-notifications/functional-design/rules.md > BR1.3 and BR3.2 (with functional-spec.md > W4 step 5) | The server skips push when `is_visible` is true. The visible flag in `justchess/live.py` is only updated by a client `visibility` message, and a socket stays "connected" until the receive timeout. If a phone tab is backgrounded or frozen and the hidden message never arrives, the server marks the claim skipped. The page is then hidden with a push subscription, so W4 step 5 makes it do nothing. The alert is lost, which is the main FR6.4 and FR6.5 scenario. | Remove the single point of failure. Either let a hidden page always show a local notification with the event-key tag (the same tag makes a duplicate replace the push), or have a hidden page act when the server says the claim was skipped. | R-02 | Major | aidlc/spaces/default/intents/261112-p1-ui-redesign/construction/u5-notifications/functional-design/rules.md > BR2.1 (subscribe validation) and BR1.4 (send) | Endpoint validation is only syntactic (https, has a dot, not an IP literal, not localhost or .local). Any dotted name that resolves to a private address (for example `127.0.0.1.nip.io`, an internal DNS name, or a cloud metadata host) passes. Any player holds a seat token, so they can make the server POST encrypted payloads to arbitrary hosts and ports. There is no mention of redirect handling or of a host allowlist for the push services. | Restrict endpoints to known push-service host suffixes (FCM, Mozilla autopush, Windows, Apple), or resolve the host at send time and refuse private, loopback and link-local addresses. Disable redirect following, reject userinfo and non-443 ports, and add tests for these cases. | New |
| R-03 | Minor | aidlc/spaces/default/intents/261112-p1-ui-redesign/construction/u5-notifications/functional-design/functional-spec.md > Boundaries (U1 api row) and Edge cases (push service is slow) | The spec says HttpApi calls `dispatch` "with `asyncio.to_thread`". The edge case says the response is not delayed because dispatch starts after the response is ready. A FastAPI handler runs nothing after `return` unless it uses a background task, and awaiting `to_thread` in the handler would hold the response for up to 10 s per subscription, 5 sequentially. The task reference, the shared thread pool and the read of hub state from a worker thread are not addressed. | State that dispatch is scheduled as a background task or a retained fire-and-forget task. Send the subscriptions with bounded concurrency, and read presence on the event loop before handing off to the thread. | New |
| R-04 | Minor | aidlc/spaces/default/intents/261112-p1-ui-redesign/construction/u5-notifications/functional-design/rules.md > BR3.3 | The service worker tag equals the bare event key (`joined`, `move:3:17`). Keys are not unique across rooms, so a notification from one room replaces another room's notification. The worker also silently skips a push when a visible page exists, and Chrome with `userVisibleOnly` then shows a generic "site updated in the background" notification. | Include the room code in the tag, in both the server payload and the client key (for example `<code>:<key>`). Decide what the worker does on the skip path, such as showing and immediately closing a notification, and note the Chrome behaviour. | New |
| R-05 | Minor | aidlc/spaces/default/intents/261112-p1-ui-redesign/construction/u5-notifications/functional-design/functional-spec.md > Boundaries (U1 db row), W2 | The in-place v2 to v3 upgrade changes `prepare_database`, which today moves aside any database whose version differs, and amends accepted ADR-006 without recording that. Add a test that a crash mid-upgrade leaves a v2 database. | New |
| R-06 | Minor | aidlc/spaces/default/intents/261112-p1-ui-redesign/construction/u5-notifications/functional-design/rules.md > BR2.1, BR2.2 | A subscription is keyed to (room, slot), not to a token. ### Summary

Coverage of FR6.1 to FR6.8, NFR3 and NFR3a is complete and the claim-before-send design is sound.
