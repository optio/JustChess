### Summary

The design covers the FRs, and its token handling and seat authorization are sound. Three gaps would cause rework or runtime faults. The first is a pending request that survives switching back to "waiting", which can end in a duplicate seat-B insert. The second is `counted` flipping on a finished practice game, with no rule for starting another pass-along game. The third is that the proxy-aware rate limit ignores uvicorn's own proxy-header handling. The remaining items are minor clarifications.
